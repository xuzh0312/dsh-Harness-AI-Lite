# 开发与测试材料

非软件本体的开发与验证材料放在此区，按需建目录，不预建固定子目录。工作区创建时仅补写本 README。获准新建 test 仓库时，按下列范围配置并核对 `.gitignore`：

- **可版本化源码**：`test/src/` 是预留入口，按需创建，只放经确认可共享的测试和辅助工具源码。
- **可共享的批准用设计稿**放在 `test/approved-designs/`。此目录按需创建，默认允许 Git 跟踪，仅放已获准共享的选定版本及其必要资源。
- **其他持久材料**：样例数据、设计草稿和脱敏验证证据放在上述两个入口外，默认忽略。获授权且适合共享的少量文件可单独放行。
- **可丢弃输出**：缓存、普通构建输出、中间产物、原始日志、截图录像及临时实验输出放在上述两个入口外，与持久材料分开，默认忽略。

选定稿作为批准依据前，核实能从 test 仓库的具体提交或获准的受控备份恢复该版及必要资源。第 3 步先在 UI/UX 方案中记录，第 5 步起由 PLAN 引用；独立任务记在 TASK。记下 test 相对路径、提交或备份版本、内容校验值和恢复位置。含敏感信息或大文件的稿件默认留在忽略区，使用获准的受控备份。仅有工作树文件或校验值时，先取得留存授权，或请用户确认以规格或任务记录中可独立验收的文字要求为准。批准、首次派工及恢复实施前，都按固定版本取回稿件和必要资源，核对其内容校验值。版本无法取回或内容不符时，暂停依赖该稿的批准与实施，直到恢复原版或用户确认独立文字依据。换稿改变验收依据时，重新确认受影响范围。

本区是独立的 test Git 仓库，仓库根即 test 根。需留存的源码和材料，核实由 test 仓库跟踪；未入仓或不宜入仓时采用受控备份，记录位置和恢复方式。仓库尚未初始化时报告并等待授权，不自行建仓；提交同样需要授权。未分类文件放在上述两个入口外，默认忽略。大文件和敏感数据默认不入仓、不分发，保留与备份须经授权。接入时保留既有测试的跟踪状态，不擅自清理。

执行测试时明确软件代码与本目录的实际路径。持久证据标明代码版本（未提交时记录基线与受验证的工作树范围），需要时关联制品标识；任务记录按 `test` 根下的相对位置引用证据，避免写入敏感名称。简要任务与错误记录保存在 harness，最终 ZIP 的授权、存放及独立验证按 harness/ARCHITECTURE.md 执行。工具无法遵守目录要求时先报告冲突。
