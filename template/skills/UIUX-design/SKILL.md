# UIUX-design · 项目体验与界面设计

交互规划家在第 3 步或用户单独委托设计时读取本入口。先读同一功能的访谈、参考、功能与技术栈报告，沿用已确认结论。直接与用户访谈，一次一题，不要求重述已有答案。

## 和用户一起设计

1. **从一次使用经历开始。** 先问用户上一次怎样完成这件事。顺着回答追问从哪里进入、需要先看什么、用什么判断成功。每题聚焦一处，再用最容易出错的步骤追问恢复方式。
2. **弄清视觉和反馈偏好。** 根据工作流追问首屏主次和需反馈的操作。同时请用户选择比较强、普通或弱动效，听完理由再挑素材。三种强度都保留必要反馈。配色、层次等影响方向时逐项谈，已明确或委托的决定直接沿用。
3. **比较方向。** 根据用户任务、内容、平台和已有选择，从[素材目录](assets/index.md)借鉴寻找合适的方案，但不允许直接抄袭，可以原创。用相同内容、状态和视口说明通常 2–3 套有实质差异的方案、各自得失和推荐理由。等用户选定、组合、提出新方向或明确委托代选，再细化。沿用已有定稿时只谈受影响之处。
4. **看稿后再展开。** 制定完成后询问用户是否需要先制作代表页。获准出稿且已指定 test 写入范围时，由交互规划家派[执行者](../../agents/implementer/AGENT.md)做代表页，单独问用户想保留或调整什么，收到反馈后修改代表页，按已授权范围迭代，直到用户确认方向或明确暂停。拖动、撤销等需要实际操作才能判断时，按委托做最小原型。
5. **交接。** 沿关键路径和一次失败恢复核对所选方向。有矛盾或例外时，追问依据和例外。收敛前单独问用户还想补充或深入哪一步，等答复再交接已选方向、关键状态和待验证项。独立设计委托也按此收敛。交互规划家将用户取舍与待实测场景写入[UI/UX 方案](../../docs/specs/README.md)，新增行为或验收变化按规划流程确认。项目稿件、原型和走查证据按[路径表](../../docs/paths.md)放在 test，选定稿将用作批准依据时，按 test/README.md 固定并核实可恢复的版本，再交接给任务规划家关联相应验收项。实施另按授权执行。
6. **结束对话。** 方案生成后判断第 3 步是否已完成。完成时明确告知用户本步结果与下一步入口，本轮不自动进入下一步。

## 遇到问题时再读

| 当前要决定什么 | 专项资料 |
| --- | --- |
| 用户真正想完成什么，入口怎么组织，如何观察他能否完成 | [任务、导航与走查](references/tasks-navigation.md) |
| 页面怎样体现这个产品，如何借鉴素材后形成原创方向 | [创意方向与素材](references/creative-direction.md) |
| 信息怎样分主次，中文、数字、配色和窄屏怎么处理 | [排版、色彩与布局](references/visual-hierarchy.md) |
| 表单何时提示，空状态写什么，错误后如何恢复焦点 | [文案、状态与无障碍](references/copy-and-states.md) |
| 操作要不要动，手势怎样跟手、中断和降动效 | [交互与动效](references/interaction-motion.md) |

引用素材时说明借用了什么原理、为当前任务改了什么，不照搬整页或成套样式。
