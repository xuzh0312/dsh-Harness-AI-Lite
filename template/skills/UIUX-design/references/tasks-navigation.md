# 任务、导航与走查

**使用时机**　讨论功能范围、用户找不到入口，或准备检验原型是否好用时。

**从一次经历开始。** 问“上一次遇到这件事时，你在哪里，手上有什么，最后怎么解决？”记录触发、已有办法、阻碍与结果。将“想要提醒”追到具体时刻，才知道所需功能是到时通知、续接进度，还是找回内容。区分用户说过的事实、观察到的行为和待验证假设。

**把任务画到刚好够用。** 写成“入口 → 判断所需信息 → 主要操作 → 可辨认结果”，再挑一处容易出错的情况补恢复路径。对每个拟加功能问：去掉它，用户在哪一步无法完成任务？把答案交用户取舍。若现有流程已覆盖目标，保留它。

**以用户找东西的方式组织入口。** 对照用户实际用词，判断他是找一个已知对象、按类别浏览，还是依次办事。让同一级栏目采用可理解的分类依据。两个入口总让人犹豫时，用几项实际内容让用户归类，观察他把东西放在哪、叫它什么。

**用任务验证。** 例如只给出“找回昨天答错的那一题”，观察第一步、停顿和恢复，不提示目标按钮。检验入口能否被发现时，先让未看过步骤的人尝试，再对照验收场景；已看过步骤的记为引导走查，模拟走查只记假设。交接时用一个可复现的场景描述最关键的障碍。
