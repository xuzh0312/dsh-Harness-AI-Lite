# 从任意会话接手

填好项目简介和热路径后，新会话可复制以下短句并补上实际 Harness 路径。用户直接选择对话工具；不要求六步由同一实例执行，也不假设不同工具共享聊天或自动加载本规则。

```text
请先读 <Harness 实际路径>/AGENTS.md 和 docs/paths.md（热路径）。
本次目标：<项目首版或某个已有功能的增量；如有编号请写明>。
这次只做：<访谈／功能与栈／UI/UX／项目方案／拆 Plan／执行获准项>。
已有材料或纠正：<可给文件或结论，不必复述旧对话>。
允许写入及检查：<分别说明；只读、不可测试、只许做模拟稿等在此说明>。
请用本次目标和已有文件判断进度；相互矛盾就先问我。结束时告诉我下一次打开哪份文件。
```

| 我想从哪里接 | 可直接放在“这次只做”里的话 |
| --- | --- |
| 1 从零或加功能 | 作为任务规划家先和我做需求访谈，边聊边记；再和我决定要不要调研开源项目。 |
| 2 换人确认选型 | 根据这次的访谈和参考记录，与我讨论并确定具体功能和技术栈；关键选型等我确认后再写成定案。 |
| 3 讨论界面 | 作为交互规划家，根据前三份材料与我定 UI/UX；我需要预览时再安排执行者。 |
| 4 整理或复核 | 把已确认的功能与栈、UI/UX 合成项目方案，检查可行性。若我说“只复核”，就不要改稿。 |
| 5 拆任务 | 根据这版项目方案拆出实施 Plan，列清每项如何审核；先不要实施。 |
| 6 开始执行 | 作为统筹执行家，核对我批准的方案和 Plan 版本；我授权实施其中的 <清单项>，按原 Plan 派工、双审和验收。 |

如果是按既有契约修复缺陷而不是新增功能，可说：“作为统筹执行家，按原契约和此前的 TASK 续修这个问题，不改变功能与验收范围。”

跨目录时按[路径登记](../paths.md)核实 harness、project、实际代码根和 test 的位置、权限及适用规则，不假定相邻。必要时补充子 agent 使用约定的既有依据、在途写入者、证据版本及额外交付授权；不要把示例文字当作真实授权。运行器无法按约定创建子实例或完成强制独立审查时，报告具体阻塞。
