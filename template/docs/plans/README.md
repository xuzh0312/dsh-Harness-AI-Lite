# 编号、执行记录与归档

- **PLAN** 用于首版或新增功能。第一份材料获准落盘时，由一位任务规划家取得本次[热路径](../paths.md)登记的独占写入交接，在同一轮内完成：重读热表并按范围查重 → 有同功能就续用 → 确是新功能才占号 → 创建首份材料并登记真实入口 → 释放写入。不把“查重”和“登记”分给两个同时办的会话；不能判断是否同一功能就问用户。占号中断或热表不可写时，先核实遗留目录的归属及写入者，不能另开第二号绕过。新编号按 `docs/specs/` 的编号目录、同号方案文件以及 `plans/active/`、`plans/completed/` 的文件名取 PLAN 最大数加一（初始 0001）。只核对名字，不读取冷档正文。写入者串行创建尚未占用的 `docs/specs/<ID>/` 来占号；若已存在，重读后重试，不覆盖。已取消编号仍占用；旧项目已有规格或 Plan 时沿用其编号，不因换人、返工或补文档重编。
- 产物分别在[规定步骤](../specs/README.md)形成。第 5 步才创建 `active/<ID>.md`；规格和计划同号、分别版本化。清单项如 `PLAN-0001.01`，引用方案 AC。其后批准、派工、审查和进度集中在原 Plan。只读时先用对话内标识，不占正式编号。
- **TASK** 仅供不属于功能 Plan 的独立工作（如按原契约修复缺陷）需要审查、返工或跨会话交接时使用。`active/TASK-0001.md` 记录用户要求与授权、基线、改动、适用的两份审查、证据、状态及下一步。获准落盘后在同一 Harness 副本按需创建 `docs/plans/task-ids/`。读取 `task-ids/`、`active/`、`completed/` 中已有 TASK 编号（兼容无占号文件的旧记录），取最大数加一，初始 0001。用原子独占创建 `task-ids/TASK-<号>.id` 永久占号（如 `FileMode.CreateNew`）；已存在就重新取号，只有创建成功者可新建同号 active 文件，不覆盖旧记录。占号文件随任务记录一同保留和备份，不因归档、取消或占号后中断而移动、删除或复用；允许跳号。无占号写权限或不能保证独占创建时不分配正式编号。切换规则前先确认旧写入者均已停写。已取消编号仍占用，不替新增功能绕过 Plan。普通问答免建。
- 完成或取消后将已有 Plan 或 TASK 同名归入 completed，更新方案状态及双向引用；规格和阶段资料保留原位。Plan 形成前取消则只更新已有阶段材料，不补造 Plan。取消前确认相关实例已停写。按[冷热路径规则](../paths.md)调整索引，仍被活跃功能引用的基线、证据不能归冷。
