## 工作区域

- harness：项目介绍、规则、需求、计划、决策、角色和技能说明。UIUX-design 的可复用资料与精选素材随技能分发。
- project/code：软件本体的源码、运行所需资源及必要的项目描述、依赖清单和构建配置，以及作为交付软件运行入口的文件（如项目要求的启动 .exe）。
- project/installpark：用户明确要求打包后生成的最终安装包。
- test：所有非软件本体的代码、测试数据、原始日志、缓存、临时输出和验证材料。项目设计稿、交互原型、走查截图与普通构建产生的可执行文件均在此区。

实际位置见 [路径表](docs/paths.md)。三个区域可跨磁盘，不假定相邻目录。接入已有项目时，可将 `project/code` 映射到现有软件代码根，无需搬迁或重建仓库；映射不改变文件归属或写入授权。

“项目代码”仅指实现交付软件本体功能的代码，包括编译后进入软件或运行时被软件使用的实现。源文件不必原样进入安装包。必要的资源、项目描述、依赖清单与构建配置属于配套文件，不因此将测试或工具代码划为软件本体。

test 中持久材料与可丢弃输出分开，按需建目录；版本化源码入口及备份规则见 test 的 README。接入时保留已有测试的位置和跟踪状态。必要的固定目录冲突先报告，由用户确认后在路径表登记；未获例外的新测试、辅助工具和输出仍放 test。

只有用户明确要求打包，或当前实施授权覆盖打包项时，才将最终 ZIP 写入 project/installpark。批准含打包项的计划不等于授权执行。解压核对和中间文件放 test。记录实际 ZIP 的标识（如校验值），核对归档格式与内容；在与源码和构建目录分离的 test 位置，从解包后的入口检查启动或安装，不依赖源码树或构建产物。同版本功能证据不替代制品检查；未运行项如实记录。打包不自动授权发布。

## Git 与执行

harness、project/code 和 test 分别使用独立 Git 仓库。test 仓库以 test 根为仓库根，默认跟踪范围为 README、`src/`、`approved-designs/` 及单独放行的文件。新建 test 仓库时，经授权按此范围配置并核对 `.gitignore`。project/installpark 不属于任何仓库，安装包独立保存。跨仓库记录引用同一 PLAN 或 TASK 编号及各自版本，编号与归档见[任务记录](docs/plans/README.md)；未经任务授权不初始化、迁移或删除仓库。

统筹执行家负责分派与最终验收，子 agent 职责见 [角色协议](agents/README.md)。工作目录按任务选择，规则加载和目录权限分别确认。对话角色按当前步骤显式读取各自文档，子角色由派工者显式指定，不是原生运行器配置。
