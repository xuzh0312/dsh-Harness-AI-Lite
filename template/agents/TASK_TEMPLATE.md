# 子任务交接

新实例只拿当前项，不转发整段聊天。已有简报给文件、版本和段落；仅路径不通时可给接收方有权查看的必要原文。材料不足则指出缺口，不绕过权限。

```text
任务：<角色、当前项、要交付的结果和验收；有批准组合时标明版本及授权项>
边界：<实际工作目录、适用规则、可读写范围、需保留的已有改动、允许的检查>
依据：<基线、相关 AC、必要接口或前置结果、证据位置；共用路径和约束可引用>
```

按角色补材料，不填无关字段：

- 预览（执行者）：交互规划家提供用户任务、待比较的状态、已定取舍、test 下允许写的位置与查看方式；本次不是生产实现。
- 实现：本项契约、输入与预期结果；修缺陷时给复现条件、已排除的假设及证据。派工时，涉及共享行为或历史易错点，给出相关调用方、已有测试或匹配的 BUG 编号，说明本次必须保住的行为。
- 审查：指定规格或质量维度、逐项或整体。两个只读实例共用同一基线至受审版本的完整差异、要求原文、执行结果和原始证据，不提供对方结论。获准生成验证产物时，为各实例指定不同输出位置。

原实例返工只补发现、变化、当前版本和复验目标；换实例或材料已失效时补齐仍有效的简报。按[共享协议](README.md)回报。
